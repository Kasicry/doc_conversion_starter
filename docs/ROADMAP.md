# PDF 문서 변환 서비스 로드맵

## 1. 로드맵 개요

본 로드맵은 PDF를 수정 가능한 문서로 변환하는 서비스를 MVP부터 상용화 단계까지 개발하기 위한 실행 계획이다. 초기에는 Next.js 프론트엔드, Spring Boot 백엔드, PostgreSQL 데이터베이스를 기준으로 PDF to DOCX와 OCR 변환에 집중하고, 이후 HWP 대응, 표 추출, 보안 기능, 기업용 API로 확장한다.

## 2. 단계별 계획

### Phase 0. 기획 및 기술 검증

목표: 핵심 변환 품질과 기술 선택지를 검증한다.

- PDF 샘플 문서 세트 수집
- 일반 PDF, 스캔 PDF, 표 중심 PDF, 관공서 문서, 계약서 샘플 분류
- Java 기반 PDF 텍스트 추출 라이브러리 비교
- Java 기반 DOCX 생성 방식 검증
- OCR 엔진 후보 비교
- HWP 변환 가능성 조사
- 변환 품질 평가 기준 정의
- Spring Boot API 구조 설계
- PostgreSQL 작업 상태 모델 설계
- 변환 엔진 모듈 경계 설계
- Python 또는 외부 변환 worker 분리 가능성 검토

완료 기준:

- PDF to DOCX 변환 PoC 완료
- 스캔 PDF OCR PoC 완료
- 표 추출 PoC 완료
- Next.js, Spring Boot, PostgreSQL 기반 MVP 기술 스택 세부 결정
- Java 기반 변환으로 MVP를 진행할 수 있는지 판단
- 외부 변환 worker가 필요한 경우 분리 기준 정의

### Phase 1. MVP 개발

목표: 사용자가 PDF를 업로드하고 DOCX 또는 OCR 결과를 다운로드할 수 있는 최소 제품을 만든다.

- 웹 업로드 화면 구현
- Spring Boot API 서버 구현
- PostgreSQL 스키마 구성
- PDF 파일 검증 구현
- 파일 저장소 구성
- PostgreSQL 기반 변환 작업 상태 관리 구현
- 변환 작업 처리 방식 구성
- PDF 분석 기능 구현
- PDF to DOCX 변환 구현
- 스캔 PDF OCR 변환 구현
- 변환 상태 조회 구현
- 결과 파일 다운로드 구현
- 파일 자동 삭제 배치 구현
- 기본 오류 처리와 사용자 메시지 구현

완료 기준:

- 사용자가 PDF를 업로드할 수 있다.
- 텍스트 기반 PDF를 DOCX로 변환할 수 있다.
- 이미지 기반 PDF를 OCR 처리해 TXT 또는 DOCX로 받을 수 있다.
- 변환 상태와 실패 사유를 확인할 수 있다.
- PostgreSQL에 파일과 변환 작업 상태가 저장된다.
- 업로드 파일과 결과 파일이 정책에 따라 자동 삭제된다.

### Phase 2. 변환 품질 개선

목표: 실제 사용 가능한 편집 품질을 높인다.

- 문단, 제목, 목록 구조 복원 개선
- 표 구조 인식 및 DOCX 표 변환 개선
- 이미지, 도장, 서명 위치 보존 개선
- 1장 PDF 입력 시 DOCX 결과도 1장으로 유지하는 편집 우선 변환 규칙 적용
- 레이아웃 유지 모드 구현
- 편집 우선 모드 구현
- OCR 전처리 추가
- 페이지 회전 자동 감지
- 변환 품질 회귀 테스트 세트 구축
- Java 기반 변환 품질 한계 분석
- 필요 시 Python 또는 LibreOffice 기반 변환 worker 분리 PoC

완료 기준:

- 주요 테스트 문서에서 문단과 표가 편집 가능한 형태로 변환된다.
- 1장 샘플 PDF는 Microsoft Word와 LibreOffice Writer 검증 기준 1장 DOCX/PDF 결과로 유지된다.
- 레이아웃 유지 모드와 편집 우선 모드를 선택할 수 있다.
- 변환 품질 회귀 테스트를 반복 실행할 수 있다.
- 변환 worker 분리 여부를 결정할 수 있다.

### Phase 3. HWP 및 한국 문서 특화

목표: 한국 사용자에게 중요한 HWP와 관공서 문서 대응을 강화한다.

- HWP 직접 생성 가능성 검증
- HWP 변환 라이브러리 또는 외부 도구 조사
- DOCX to HWP 대체 흐름 설계
- LibreOffice 기반 DOCX to HWP 직접 export filter 부재 확인
- HWP 직접 지원 전까지 DOCX 대체 제공 정책 정리
- 공문, 신청서, 계약서 문서 유형별 변환 규칙 개선
- 한국어 OCR 사전 및 후처리 규칙 개선
- 문서 내 날짜, 금액, 전화번호 형식 보존 개선

완료 기준:

- 사용자가 HWP 편집을 목적으로 변환 결과를 받을 수 있다.
- 한국어 문서 변환 품질이 MVP 대비 개선된다.
- HWP 직접 지원 여부에 대한 제품 정책이 결정된다.

### Phase 4. 표 추출 및 문서 도구 확장

목표: PDF 변환 외의 고가치 문서 작업을 제공한다.

- PDF 표 감지 기능 구현
- PDF to XLSX 변환 구현
- PDF to CSV 변환 구현
- 페이지 범위 선택 구현
- PDF 병합 기능 구현
- PDF 분할 기능 구현
- 이미지 추출 기능 구현
- 텍스트 추출 기능 구현
- 결과 ZIP 다운로드 구현

완료 기준:

- 표 중심 PDF를 XLSX 또는 CSV로 추출할 수 있다.
- 사용자가 페이지 단위로 변환 범위를 선택할 수 있다.
- 여러 결과 파일을 ZIP으로 받을 수 있다.

### Phase 5. 미리보기 및 사용자 검수

목표: 변환 전후 품질 확인과 사용자 제어를 강화한다.

- PDF 페이지 미리보기 구현
- 페이지 회전, 삭제, 순서 변경 구현
- 원본 PDF와 변환 결과 비교 화면 구현
- OCR 신뢰도 낮은 영역 표시
- OCR 결과 간단 수정 기능 구현
- 변환 옵션 프리셋 제공

완료 기준:

- 사용자가 변환 전에 페이지를 정리할 수 있다.
- 원본과 변환 결과를 비교할 수 있다.
- OCR 오류 가능성이 높은 영역을 확인할 수 있다.

### Phase 6. 보안 및 개인정보 기능

목표: 민감 문서 처리에 대한 신뢰를 높인다.

- 즉시 삭제 기능 구현
- 파일 보관 시간 설정 구현
- 개인정보 패턴 감지 구현
- 주민등록번호, 전화번호, 이메일, 계좌번호 마스킹 구현
- 다운로드 URL 만료 정책 강화
- 악성 파일 검사 연동 검토
- 감사 로그 설계

완료 기준:

- 사용자가 업로드 파일과 결과 파일을 직접 삭제할 수 있다.
- 개인정보 자동 마스킹 결과를 받을 수 있다.
- 파일 접근과 삭제 정책이 사용자에게 명확히 안내된다.

### Phase 7. 일괄 변환 및 유료화

목표: 반복 작업 사용자와 유료 사용자를 지원한다.

- 다중 파일 업로드 구현
- 파일별 변환 상태 표시
- 일괄 변환 작업 큐 최적화
- ZIP 다운로드 구현
- 사용자 계정 기능 구현
- 변환 이력 구현
- 무료 사용량 제한 구현
- 유료 플랜 정책 구현
- 결제 연동 구현

완료 기준:

- 여러 PDF를 한 번에 변환할 수 있다.
- 사용자는 변환 이력을 확인할 수 있다.
- 무료 및 유료 플랜 제한이 적용된다.

### Phase 8. 기업용 API 및 관리자 기능

목표: 기업 고객과 외부 시스템 연동을 지원한다.

- API 키 발급 및 관리 구현
- 파일 업로드 API 구현
- 변환 요청 API 구현
- 작업 상태 조회 API 구현
- 결과 다운로드 API 구현
- API 요청량 제한 구현
- 팀 및 권한 관리 구현
- 관리자 대시보드 구현
- 기업용 파일 미보관 옵션 구현

완료 기준:

- 기업 고객이 API로 문서 변환을 사용할 수 있다.
- 관리자와 팀 사용자가 사용량과 이력을 관리할 수 있다.
- 요금제별 API 제한이 적용된다.

## 5. 핵심 의사결정 항목

- OCR 엔진: 클라우드 API를 사용할지 자체 호스팅할지 결정
- HWP 지원: 직접 HWP 생성과 DOCX 대체 경로 중 초기 전략 결정
- 파일 저장소: 로컬, 오브젝트 스토리지, 임시 저장소 중 선택
- 변환 작업 처리: Spring Boot 내부 비동기 처리, Spring Batch, PostgreSQL polling, 메시지 큐 기반 worker 중 선택
- 변환 엔진: Java 내부 모듈 유지와 Python 또는 외부 worker 분리 중 선택
- 과금 기준: 파일 수, 페이지 수, 용량, OCR 사용량 중 선택
- 보관 정책: 기본 자동 삭제 시간과 기업용 미보관 옵션 결정

## 6. 기술 검토 후보

- 프론트엔드: Next.js, TypeScript, Tailwind CSS
- 백엔드: Spring Boot, Spring Web, Spring Validation, Spring Security
- 데이터베이스: PostgreSQL
- DB 마이그레이션: Flyway
- 빌드 도구: Gradle
- ORM/데이터 접근: Spring Data JPA, JDBC
- PDF 분석: Apache PDFBox
- DOCX 생성: Apache POI, docx4j
- OCR: Tess4J, Tesseract, PaddleOCR worker, Google Cloud Vision, AWS Textract, Azure AI Vision
- 문서 변환 보조: LibreOffice headless, JODConverter, Pandoc
- 표 추출: Apache PDFBox 기반 추출, Tabula, Camelot 또는 Python worker
- 작업 처리: Spring `@Async`, Spring Batch, PostgreSQL polling, RabbitMQ, Redis
- 운영 모니터링: Spring Boot Actuator
- 저장소: 로컬 임시 저장소, S3 호환 오브젝트 스토리지
