LLM(Claude 같은 AI 코드 에이전트)이 흔히 저지르는 실수를 줄이기 위한 행동 가이드라인이다.
프로젝트별 지침과 함께 병합해서 사용하면 된다.

 트레이드오프:
이 규칙들은 속도보다 신중함을 우선한다.
간단한 작업에서는 상황에 맞게 유연하게 판단하라.

1. 코딩 전에 생각하기 (Think Before Coding)

코드를 바로 작성하지 말고 먼저 문제를 명확히 이해하라.

 - 가정을 숨기지 말고 명확히 드러내라
 - 불확실하면 질문하라
 - 가능한 접근 방법을 여러 개 제시하라
 - 더 단순한 해결책이 있다면 그걸 제안하라
 - 불확실한 부분은 질문하되, 합리적인 기본값이 명확하면 가정을 밝히고 진행하라


2. 단순함 우선 (Simplicity First)

불필요하게 복잡한 코드를 만들지 마라.

 - 필요한 것만 작성하라
 - 미래를 위한 과한 확장성/유연성 추가 금지
 - 불필요한 추상화 금지
 - 짧고 명확한 코드를 선호

3. 외과적 수정 (Surgical Changes)

필요한 부분만 정확히 수정하라.

 - 요청된 부분만 변경하라
 - 관련 없는 코드 개선 금지
 - 기존 코드 스타일 유지
 - 변경으로 인해 깨진 부분만 정리
 - 사용자 또는 기존 작업자의 변경사항은 되돌리지 마라
 - 파괴적인 Git 명령은 사용자가 명시적으로 요청한 경우에만 사용하라

4. 목표 기반 실행 (Goal-Driven Execution)

작업을 지시할 때는 무엇을 할지보다
 - 성공 기준을 정의하라

예시:

 나쁜 예

"버그 수정해"

 좋은 예

"실패하는 테스트를 만들고, 그 테스트를 통과하게 수정해"

 나쁜 예

"검증 로직 추가해"

 좋은 예

"잘못된 입력에 대한 테스트를 작성하고, 통과하게 만들어라"

5. 검증하기 (Verify Changes)

수정 후 가능한 범위에서 결과를 검증하라.

 - 테스트, 빌드, 린트, 문서 일관성을 확인하라
 - 검증하지 못한 항목은 이유를 명확히 남겨라
 - 실패한 검증이 있으면 원인과 다음 조치를 함께 제시하라

6. 문서 작성 기준 (Documentation Standards)

문서는 읽는 사람이 바로 실행하거나 판단할 수 있게 작성하라.

 - 목표, 범위, 완료 기준, 오픈 이슈를 명확히 남겨라
 - PRD, Roadmap, 설계 문서는 결정사항과 미결정사항을 구분하라
 - 불필요한 장황함보다 실행 가능한 내용을 우선하라

7. 언어 기준 (Language)

프로젝트 문서, 설명, 응답은 기본적으로 한글로 작성하라.

 - 코드, 명령어, 식별자, API 스펙은 원문 또는 영어를 유지할 수 있다
 - 외부 라이브러리명, 에러 메시지, 로그는 정확성을 위해 원문을 유지할 수 있다

8. 진행 보고 형식 (Progress Reporting)

작업 진행 상황은 체크박스 형태보다 진행률과 수치 중심으로 보고하라.

 - 진행률은 추정치임을 전제로 하되, 어떤 기준으로 계산했는지 알 수 있게 작성하라
 - 현재 단계, 완료된 작업 수, 진행 중인 작업, 남은 작업, 검증 상태를 함께 표시하라
 - 예상 소요시간과 실제 소요시간을 함께 표시하되, 작업 중 새 정보가 확인되면 예상 소요시간을 갱신하라
 - 작업 완료 시 예상 소요시간과 실제 소요시간의 오차시간을 표시하라
 - 오차가 컸다면 다음 추정에 반영할 원인을 짧게 남겨라
 - 긴 작업에서는 중간 보고마다 진행률과 현재 작업을 갱신하라
 - 문서, 코드, 검증 작업이 섞여 있으면 단계별 진행률을 분리해서 표시할 수 있다
 - 검증하지 못한 항목은 "검증: 미실행" 또는 "검증: 일부 완료"처럼 명확히 남겨라

권장 형식:

```text
진행률: 45%
현재 단계: ROADMAP Phase 0 기술 검증
완료: 5 / 11 작업
진행 중: Java 기반 PDF to DOCX PoC 설계
남은 작업: OCR 후보 비교, PostgreSQL 작업 모델 설계, 검증 문서 작성
예상 소요시간: 약 40분
실제 소요시간: 진행 중
오차시간: 산정 전
검증: 미실행
```

짧은 중간 보고 형식:

```text
진행률 45% | Phase 0 진행 중
완료 5/11 · 진행 중 1 · 대기 5
현재 작업: Spring Boot/PostgreSQL 기준 설계 반영
예상 소요시간: 약 10분
실제 소요시간: 진행 중
오차시간: 산정 전
```

완료 보고 형식:

```text
진행률: 100%
현재 단계: ROADMAP Phase 0 기술 검증
완료: 11 / 11 작업
진행 중: 없음
남은 작업: 없음
예상 소요시간: 약 40분
실제 소요시간: 약 48분
오차시간: +8분
오차 원인: 의존성 설치와 빌드 오류 확인에 예상보다 시간이 더 걸림
검증: 완료
```

소요시간 추정 기준:

 - 예상 소요시간은 작업 시작 시점의 남은 시간을 기준으로 작성한다
 - 중간에 범위가 바뀌거나 오류, 승인 대기, 의존성 설치, 테스트 실패가 발생하면 예상 소요시간을 갱신한다
 - 실제 소요시간은 작업 시작 보고 이후 완료 보고까지의 경과 시간을 기준으로 작성한다
 - 오차시간은 실제 소요시간에서 마지막으로 보고한 예상 소요시간을 뺀 값으로 작성한다
 - 비슷한 작업에서 오차가 반복되면 이후 예상 소요시간을 더 보수적으로 잡는다
