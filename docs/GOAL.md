# 프로젝트 목표

## 1. 최종 목표

PDF 파일을 수정 가능한 문서 형식으로 변환하는 웹 서비스를 구축한다.

1차 목표는 PDF를 DOCX, HWP 등 편집 가능한 문서로 변환하는 것이다. 이후 표 추출, OCR 품질 개선, 개인정보 마스킹, 일괄 변환, 기업용 API로 확장한다.

## 2. 진행 기준

- [ROADMAP.md](./ROADMAP.md)를 기준으로 Phase 0부터 순차 진행한다.
- [PRD.md](./PRD.md)의 제품 목표, MVP 범위, 기능 요구사항을 기준으로 구현 범위를 판단한다.
- [agents.md](./agents.md)의 작업 원칙을 따른다.
- 프론트엔드는 Next.js와 TypeScript를 기준으로 한다.
- 백엔드는 Spring Boot를 기준으로 한다.
- 백엔드 빌드 도구는 Gradle을 기준으로 한다.
- 데이터베이스는 PostgreSQL을 기준으로 한다.
- 개발 환경 포트는 13800번대를 사용한다.
- 기본 포트는 백엔드 `13800`, 프론트엔드 `13801`, PostgreSQL 호스트 포트 `13832`로 한다.
- 변환 엔진은 초기에는 Spring Boot 내부 모듈 또는 같은 저장소의 worker 모듈로 시작하되, 필요 시 Python 또는 외부 변환 워커로 분리할 수 있게 경계를 유지한다.
- 작업 전 목표와 성공 기준을 명확히 한다.
- 작업 후 가능한 범위에서 검증 결과를 남긴다.

## 6. 작업 원칙

- 단순한 해결책을 우선한다.
- 필요한 범위만 정확히 수정한다.
- 불필요한 추상화와 과한 확장성은 추가하지 않는다.
- 기존 코드와 문서 스타일을 유지한다.
- 불확실한 부분은 명확히 드러낸다.

## 7. 완료 기준

각 작업은 다음 기준을 만족할 때 완료로 본다.

- 요청된 기능 또는 문서 변경이 반영되어 있다.
- 관련 문서의 목표, 범위, 완료 기준, 오픈 이슈가 일관된다.
- 가능한 범위에서 테스트, 빌드, 린트, 문서 구조 확인 중 필요한 검증을 수행했다.
- 검증 실패 또는 미수행 항목이 있으면 원인과 다음 조치를 기록했다.

## 8. 진행 보고 기준

앞으로 프로젝트 진행 상황은 체크박스 나열보다 수치 기반으로 보고한다.

기본 보고 형식:

```text
진행률: 45%
현재 단계: ROADMAP Phase 0 기술 검증
완료: 5 / 11 작업
진행 중: Java 기반 PDF to DOCX PoC 설계
남은 작업: OCR 후보 비교, PostgreSQL 작업 모델 설계, 검증 문서 작성
예상 소요시간: 약 40분
실제 소요시간: 진행 중
오차시간: 산정 전
검증: 미실행
```

짧은 중간 보고 형식:

```text
진행률 45% | Phase 0 진행 중
완료 5/11 · 진행 중 1 · 대기 5
현재 작업: Spring Boot/PostgreSQL 기준 설계 반영
예상 소요시간: 약 10분
실제 소요시간: 진행 중
오차시간: 산정 전
```

완료 보고 형식:

```text
진행률: 100%
현재 단계: ROADMAP Phase 0 기술 검증
완료: 11 / 11 작업
진행 중: 없음
남은 작업: 없음
예상 소요시간: 약 40분
실제 소요시간: 약 48분
오차시간: +8분
오차 원인: 의존성 설치와 빌드 오류 확인에 예상보다 시간이 더 걸림
검증: 완료
```

진행률 산정 기준:

- 짧은 작업은 완료 작업 수 / 전체 작업 수를 기준으로 계산한다.
- ROADMAP 기반 장기 작업은 현재 Phase의 완료 기준을 기준으로 계산한다.
- 여러 Phase가 섞이면 전체 진행률과 Phase별 진행률을 함께 표시한다.
- 진행률은 추정치이며, 구현 또는 검증 결과에 따라 조정할 수 있다.
- 예상 소요시간은 추정치이며, 작업 범위 변경, 의존성 설치, 테스트 실패, 외부 승인 필요 여부에 따라 갱신한다.
- 실제 소요시간은 작업 시작 보고 이후 완료 보고까지의 경과 시간을 기준으로 표시한다.
- 오차시간은 실제 소요시간에서 마지막 예상 소요시간을 뺀 값으로 표시한다.
- 오차가 큰 경우 오차 원인을 남기고, 이후 유사 작업의 예상 소요시간 산정에 반영한다.
- 승인 대기, 네트워크 지연, 의존성 설치, 테스트 실패처럼 통제하기 어려운 시간은 오차 원인에 명시한다.
- 검증 상태는 완료, 일부 완료, 미실행, 실패 중 하나로 명확히 표시한다.

## 9. 현재 기준 목표

현재 프로젝트의 실행 목표는 다음과 같다.

- Phase 0 기술 검증을 완료한다.
- MVP 구현에 필요한 세부 기술 스택을 확정한다.
- 단일 PDF 업로드부터 DOCX 또는 OCR 결과 다운로드까지 이어지는 최소 흐름을 구현한다.
- 이후 ROADMAP에 따라 변환 품질 개선, HWP 대응, 표 추출 기능으로 확장한다.
- 1장 PDF 입력은 편집 가능한 DOCX 결과도 가능한 한 1장 안에서 유지한다.
- 1장 유지 여부는 Microsoft Word와 LibreOffice Writer에서 모두 확인한다.
- HWP 직접 생성은 LibreOffice export filter 부재로 현재 지원하지 않고, DOCX 대체 경로를 우선한다.

## 10. 오픈 이슈

- OCR 엔진을 클라우드 API로 사용할지 자체 호스팅 엔진으로 사용할지 결정해야 한다.
- HWP 직접 생성은 별도 도구 또는 라이브러리 검토가 필요하다. 현재 MVP는 DOCX 기반 대체 경로를 우선한다.
- Spring Boot 내부 처리, Spring Batch, PostgreSQL polling, 메시지 큐 중 MVP 작업 처리 방식을 결정해야 한다.
- PDFBox와 Apache POI 기반 변환 PoC는 진행 중이며, 품질 한계가 확인되면 docx4j, JODConverter, 외부 worker를 추가 검토한다.
- 파일 보관 시간과 삭제 정책을 구체화해야 한다.
- 변환 품질 평가용 샘플 문서 세트를 준비해야 한다.
